# 实时电路图绘制模型（Q5 深度分析）

> 配套 [`architecture.md`](./architecture.md) v2.1
> 定位：回答**「用户真的能实时绘制工程电路图」**这一本质问题。
> 结论先行：这不是"程序画图"，而是一个**原理图捕获编辑器（Schematic Capture）**。它的技术核心不是渲染，而是 **连续的 2D 几何 → 离散电气拓扑** 的稳定映射，以及 **节点身份在编辑过程中的稳定性**。

---

## 0. 问题定义

- 鼠标输入是**连续的几何**（坐标、线段、点）。
- 电路是**离散的拓扑**（节点集合 + 支路集合 + 元件）。
- 编辑器必须：每当用户落下/移动/删除一笔，**即时且稳定地**把几何重算为拓扑，并驱动求解与可视化。

三个必须同时满足的约束：

| 约束 | 含义 | 反面案例（不可接受） |
|---|---|---|
| **实时** | 拖拽/连线过程中界面流畅（动画、吸附即时） | 每拖一下卡 1 秒 |
| **稳定** | 编辑动作不无故改变节点身份与已有引用 | 挪一下元件，`n1` 变成 `n5`，@节点与公式全错位 |
| **专业** | 连接判定符合工业 EDA 标准（Q6） | 十字交叉被误判为相连 |

## 1. 三层模型（Viewport / Schematic / Topology）

```
┌─────────────────────────────────────────────┐
│ ① 视图层 Viewport（非持久）                   │
│   zoom / pan / 网格 / 选择集 / 悬浮态 / 光标   │
├─────────────────────────────────────────────┤
│ ② 原理图层 Schematic（持久=用户画的"图"）      │
│   元件实例 / 导线 / junction / 接地 / 标注     │
│   —— 唯一被存盘、被渲染的几何真相              │
├─────────────────────────────────────────────┤
│ ③ 拓扑层 Topology（派生，可缓存）              │
│   电气节点(equipotential) / 支路 / 端子归属     │
│   —— 由 ② 通过连通规则推导，供求解器消费        │
└─────────────────────────────────────────────┘
```

**关键原则**：**存盘只存 ②**。③ 永远可由 ② 重新推导（可缓存但非真值）。这样存档不依赖任何求解器版本，也不会因为算法升级而"存档损坏"。

> 为什么不让用户直接编辑拓扑？因为用户画的是**图**，不是**网表**。允许手工改节点，等于让编辑器同时维护两套真相，必然冲突。若确需手动强制合并/拆分，用 **net label（网络标签）** 或 **junction 覆盖** 表达，仍落在 ② 层。

## 2. 几何图元与稳定 ID（层②）

每个图元在**创建时**分配一个**不随几何移动而变化**的持久 ID：

| 图元 | 字段 | 稳定 ID 示例 | 说明 |
|---|---|---|---|
| 元件实例 | type, x, y, rotation, mirror, value, unit | `c:R@3f9a` | 拖动改 x/y，ID 不变 |
| 元件端子 | 归属元件 + 引脚序号 | `c:R@3f9a/p0` | 由元件 ID + 引脚号派生 |
| 导线 | vertices[]（折线顶点表） | `w:7c21` | 一条导线 = 一条折线 |
| 导线端点 | 归属导线 + 端点序号 | `w:7c21/v0`, `w:7c21/vN` | 端点可被吸附/合并 |
| 导线折点 | 归属导线 + 顶点序号 | `w:7c21/v1` | 拐点，不参与电气连接 |
| Junction | x, y | `j:5b0e` | 显式连接点 |
| 接地 | x, y, rotation | `c:GND@....` | 接地元件，其端子强制并入节点 0 |
| 标签/端口 | x, y, text | `l:...` | 可选，用于跨页/强制命名 |

**设计要点**
- 所有 ID 与坐标**解耦**。这样层③的推导结果才能跨编辑保持稳定。
- 折点（v1..vN-1）与端点（v0, vN）语义不同：**只有端点和"落在导线上的位置"参与连接**。
- 导线允许是一整条折线（多段），但**电气语义上一条导线内的所有顶点等电位**（同一 net），直到被用户在中间插入 junction 并另接。

## 3. 几何 → 拓扑映射规则（对齐工业 EDA 标准，Q6）

层③通过两类运算得到：

### 3.1 端点吸附（几何容差）
- 网格吸附：默认网格 `g`（如 0.1 inch = 2.54mm 的屏幕映射，或 10px）。
- 吸附半径：鼠标/端点到候选端子的距离 < `R_snap`（建议 12–15px）即视为共点。
- 命中优先级：**端子 > 导线端点 > 导线内部 > 网格点**。

### 3.2 连通判定（工业标准行为，取自 KiCad/EAGLE 惯例）

| 情形 | 是否连通 | 处理 |
|---|---|---|
| 导线端点 ↔ 元件端子（共点） | ✅ | 直接连接 |
| 导线端点 ↔ 导线端点（共点） | ✅ | 两导线合并为同一 net |
| 导线端点落在**另一条导线中部**（T 接） | ✅ | **自动在该点插入 junction** 并连接（工业标准：T 接默认连通） |
| 两导线**十字交叉且都继续延伸** | ❌ | **不连通**（跨越）；需用户显式放 junction 才连通 |
| 显式 junction 点压住交叉/共点 | ✅ | 强制合并该点所有图元 |
| 接地端子 | ✅→节点 0 | 所有接地并入同一参考地 0 |
| 元件端子落到导线中部（引脚接在线中间） | ✅ | 同 T 接，插入 junction |
| 共线重叠的两段导线 | ✅ | 合并/去重 |

> 「T 接自动连、十字默认不连」是 EDA 工具的通例，也是初学者最容易画错的地方。编辑器对此**必须即时可视化反馈**（T 接处显示自动生成的 junction dot；十字交叉显示"不连通"的视觉区分）。

### 3.3 图元清洗
每次拓扑推导前做规范化，保证模型干净：
- 删除**零长度导线**；
- 合并**共线重合**的相邻段；
- 去除**悬空端点**（未连接任何东西的导线尾，可保留但标记为"未连接"）；
- 已落在导线内部的端点，先在几何层**拆分该导线**（split），使"中部接触"变成"端点接触"——这样连通判定只需处理"端点共点"一种简单情形（**推荐实现**）。

### 3.4 推导算法
1. 收集所有"连接点候选"：每个端子、每条导线的两个端点、每个 junction。
2. 对候选点按几何做空间索引（网格哈希 / 四叉树）查共点。
3. **并查集（Union-Find / DSU）**合并共点与被 junction 覆盖的点。
4. T 接 / 引脚触线：先 split 再并入。
5. 每个 DSU 集合 = 一个电气节点；含接地者 = 节点 0。
6. 输出：`node → {terminals[], wires[]}`、`branch = (compId, pinA_node, pinB_node)`。

## 4. 节点身份与稳定性 ★ 全案核心

### 4.1 为什么必须稳定
节点 ID 被四处**外部引用**：

1. 用户 `@节点` 注入（对话上下文）；
2. AI 对话历史中引用的 `V(n1)=…`；
3. 存档里的用户注解 `node_notes: {"n1": "分压点"}`；
4. 侧边栏符号公式 `V(n1) = R2/(R1+R2)·Vs`。

只要编辑导致 `n1` 被重编号，上述全部错位。**这是"用户实时画图"模式的头号风险**，必须专门设计。

### 4.2 身份模型：DERIVED + 复用映射

- 电气节点**不直接等于**任何图元，而是 DSU 集合。
- 但每轮推导后，为每个节点分配一个**面向用户与 API 的稳定 NodeID**，采用"**历史复用**"策略：

```
对每个新 DSU 集合 S：
  候选 = { 上一轮 NodeID(prev) | 该 prev 的任一成员图元 ∈ S 的成员图元 }
  若 候选 非空：
       选成员交集最大者复用（多数投票，平票取字典序最小）
  否则：
       分配新 NodeID（递增 n1, n2, ... 或 "N<自增>"）
```

- 直观效果：**拖动元件、在别处加支路** → 连通关系没变 → 节点 ID 复用，一切引用不失效。
- **真正改变连通**（用户断线重接）才可能产生新 ID，属预期行为。

### 4.3 锚点（Anchor）作为兜底
除复用外，给每个节点一个确定性"锚"用于展示与排序：
`anchor(node) = min(该节点所有成员的稳定 ID)`。
用于：
- 节点显示编号排序（`n1..nk` 按锚排序，稳定）；
- 当历史复用缺失（首次加载纯粹存档）时的初始赋值。

### 4.4 地节点
逻辑节点 `0` 恒为地；**多个接地符号全部并入 0**。地不参与复用编号（永远是 `0`/`GND`）。

### 4.5 允许改变的情形（需向用户明示）
- 用户断线重接 → 节点分裂/合并 → 相关 ID 变更 → **UI 提示"节点编号已更新"**，并同步改写注解/对话引用中的旧 ID（保留映射表 `oldID→newID`，可追溯）。
- 元件删除导致节点消失 → 该 NodeID 退役（不复用给无关节点，避免张冠李戴）。

### 4.6 与求解期的编号解耦
- **面向用户/API 用稳定 NodeID**（`n1`）。
- **送入 lcapy/SPICE 时**再映射为求解网表编号（`0` 固定地，其余 1..k）——求解编号只影响当次方程，不影响身份。**两套编号分离**是稳定性的关键设计。

## 5. 实时求解分级（配合 Q3"程序求解"）

用户画图是**实时**的，但 lcapy **符号求解慢且重**，不能每帧跑。因此分三档：

| 时机 | 求解器 | 目的 | 目标耗时 |
|---|---|---|---|
| 编辑中（拖拽/连线，去抖 ~80–150ms） | **数值 MNA（numpy，唯一实现）** | 实时节点电压/支路电流 → 动画、探针 | < 20ms |
| 编辑空闲（松手后 ~400ms） | **lcapy 符号** | 侧边栏符号式 + LaTeX | 视规模 |
| 每次数值/符号解之后 | **校验层** | 交叉校验 + 残差；异常才提示 | 轻量 |

**架构影响**：MNA 数值求解器从 v2 的"仅校验"**升级为"实时主求解器 + 校验参照"**。它必须：
- 纯 numpy、无符号开销；
- 支持 R / 独立源 / 线性受控源（第一阶段），后续扩 C/L 的 s 域与瞬态；
- 支持端口加测试源（供等效扫描复用）。

**在哪儿跑**（要在后续定案，见 §9）：
- **方案 A（推荐）**：Python 后端唯一实现，WebSocket 去抖调用。本地往返 <5ms，避免维护两份 MNA，杜绝算法分歧。
- 方案 B：前端 JS 内实现 MNA，零延迟，但与后端 lcapy 校验时需保证算法一致——**双重实现有分歧风险**。

> 无论哪种，"符号 lcapy"与"数值 MNA"都必须可交叉校验，这是可信度来源（已去除 PySpice）。

## 6. 绘制交互清单（Scratch 式元件面板 + EDA 式画布，Q4）

### 6.1 元件面板（似 Scratch 积木区）
- 左侧分类面板：电源 / 无源 / 受控源 / 测量 / 接地…
- **拖放**元件到画布，或点击后在画布点选落点。
- 放置后弹出/侧栏**参数输入**：阻值、电压/电流值、单位（Ω/kΩ/mA…）、AC 幅值相位等。
- 元件属性：位号自动命名（R1, V1…），可改。

### 6.2 画布绘制（EDA 式）
| 操作 | 交互 |
|---|---|
| 画导线 | 点端子起笔 → 折线（可加拐点）→ 点目标端子收笔（折线连线） |
| 吸附 | 端子/导线/网格三级吸附 + 高亮圆环 |
| T 接 | 导线端点落到另一导线 → 自动插入 junction |
| 放 junction | 手动工具；或自动生成（视觉上可区分） |
| 移动元件 | 拖动，导线**橡皮筋/自动正交跟随**（保连接） |
| 旋转/镜像 | `R` / `X` / `Y` |
| 删除 | `Del`，连带清理悬空导线 |
| 框选/多选 | 拖框；`Shift` 加选 |
| 复制/粘贴/再制 | `Ctrl+C/V/D` |
| 对齐/均分 | 多选时工具条 |
| 撤销/重做 | `Ctrl+Z/Y`，**命令模式**（每步是命令对象） |

### 6.3 电流/电压可视化（符合大学生学习标准，Q7）
- **电流方向采用"参考方向"（关联参考方向 / 被动符号约定）**——与《电路分析》课程一致：在元件旁标参考箭头，实际方向由求解结果取符号（负号表示与箭头相反）。**不默认画"实际方向"**，因为课程训练的是参考方向 + 符号判读。
- 动画可选：在参考方向箭头上做流动效果，方向体现**符号**而非强行翻转箭头。
- 元件旁标注 `I_R1 = 2.5mA`、`V_R1 = 2.5V`，与课程记号一致（双下标/单下标）。

## 7. 边界情况与错误反馈

| 情况 | 现象 | 处理 |
|---|---|---|
| 无地（浮空电路） | MNA/lcapy 奇异 | 明确提示"缺少参考地"，不求解 |
| 电压源短路 | 电流无穷 | 检测并高亮该回路，提示 |
| 悬空端子/孤立元件 | 不影响结果 | 黄色警告标记 |
| 重复接地 | — | 全部并入 0（正常） |
| 元件半插入（正在画） | 网表不完整 | 期间只做几何渲染，不求解 |
| 未知参数（如 R 为空） | 无法求解 | 标红，跳过该支路并在侧栏列出未完成项 |

**原则**：**求解失败绝不能让编辑器崩溃或卡死**；错误以非阻塞方式呈现。

## 8. 性能预算

| 项 | 目标 |
|---|---|
| 渲染 | `requestAnimationFrame` 60fps；小规模电路全量重绘即可，无需脏矩形 |
| 拓扑重算 | 增量：仅重算受影响节点的连通（局部 DSU）；< 1ms |
| 数值求解 | 去抖 80–150ms；单次 < 20ms（数十节点量级） |
| 符号求解 | 空闲触发，可取消；结果异步回填侧栏 |
| 撤销栈 | 命令对象，保留最近 N 步（如 100），内存可控 |

## 9. 待你后续定案的细节（不阻塞当前设计）

1. **坐标/单位体系**：屏幕像素网格 vs 真实 2.54mm/0.1inch 网格（建议后者，专业且便于导出）。
2. **折线 vs 正交布线**：允许任意角度折线（初学更自由）还是强制正交（更专业）？建议**正交为主 + 允许自由**。
3. **MNA 运行位置**：§5 方案 A（Python 唯一实现，推荐）vs B（前端 JS）。
4. **net label / 端口**：是否第一版就支持命名网络（利于复杂电路与等效端口）。
5. **导线自动跟随**：移动元件时是"橡皮筋直线"还是"自动正交重路由"（后者复杂，可后置）。

## 10. 与其它模块的接口

- **→ 求解服务**：拓扑层输出 `{nodes, branches, components}` 的规范化网表（见 architecture §7）。
- **→ AI**：稳定 NodeID 是 `@节点`与对话引用的锚；`conversation_store` 只认 NodeID，不认求解编号。
- **→ 存档**：只序列化层②（几何）与元数据；NodeID 映射表可作为缓存一并保存以加速复用判定（非真值）。
